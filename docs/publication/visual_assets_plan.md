# Visual Assets Plan

**Status: one figure produced, four screenshots planned but not captured.**

The repository tracked **zero images** before this phase. Rather than committing
whatever diagnostic PNGs happened to exist on the development machine — which would
risk publishing local paths, window titles, machine names or unvetted intermediate
results — this documents what should be captured and to what standard.

---

## Produced

### 1. Analytical vs FEMM `Ke` comparison ✅

`docs/assets/ke_validation_phase10c.png` — generated by
`work/generate_ke_validation_figure.py`.

Every number is read from
`validation_data/fea_results/phase10c_self_consistent/ke_error_decomposition.json`;
nothing is typed into the script, so re-running it after a future campaign regenerates
the figure from whatever the evidence then says.

Shows the geometry-consistent Phase 10C result (**+7.15 %**) as the headline, and the
superseded −0.22 % historical case only as a greyed component of the cancellation
explanation. Carries the solver version, fidelity tier, mesh sensitivity and the
`NUMERICAL_FEA` disclaimer in the caption.

## Planned — not yet captured

Each needs a deliberate capture pass on a clean state. Requirements common to all:

- Use the shipped startup preset (`design.manufacturability_start.v2`), not a
  scratch design
- No window title, path, username or machine name visible that identifies the
  developer's environment
- Default window size, 100 % display scaling, default theme
- PNG, lossless, no annotation burned in unless it aids comprehension

### 2. Main GUI / results dashboard
Purpose: answer "what does this actually look like" in the first screen of the README.
Capture the guided input panel plus the results dashboard with a computed result.
**Care:** the UI is Chinese-first. For an English-first README, either caption the
figure in English or capture with `en_US` locale — decide before capturing.

### 3. Feasibility and corrected-voltage dashboard
Purpose: show the engineering-judgement layer that distinguishes this from a
calculator. Should show the authoritative line-RMS voltage margin card with the
legacy value in its `兼容值` diagnostic group, and at least one severity-graded issue.

### 4. FEMM field visualization
Purpose: show that the FEA bridge drives a real solver.
Open a generated `.fem`/`.ans` from a validation workspace in the FEMM GUI and capture
the flux-density plot of the unrolled AFPM slice.
**Care:** this is a screenshot of third-party software. Caption it as such, and do not
imply FEMM is part of this project or is redistributed.

### 5. FEA validation dialog
Purpose: show the provenance and honesty machinery — case hash, fidelity tier,
approximation labels, per-target `NOT_YET_VALIDATED` status.
Good candidate for showing the solver-unavailable state too, since that path is
deliberately designed and is unusual to see documented.

## Architecture diagram

Rendered inline in the README as Mermaid rather than committed as an image. GitHub
renders Mermaid natively, it stays diffable and editable, and it cannot drift out of
sync with a stale exported PNG.

---

## Anti-goals

- No marketing-style composites or mockups
- No screenshot showing a result the validation status does not support
- No "FEA validated" badge or overlay — the validation is numerical, single-case, and
  `FEA_TIER_3`
- No screenshots of the historical −0.22 % comparison presented as a headline result
