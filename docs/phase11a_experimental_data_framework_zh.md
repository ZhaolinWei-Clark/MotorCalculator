## 1. 证据分类法（Step 3 / Part H）

本项目前十个阶段的主要成本，都花在防止「有限元结果被当成实测」上。
引入外部数据把同一个伤口重新撕开了三次，因此分类不是约定，而是结构。

| 类别 | 含义 | 是否实验证据 | 能否验证当前机器 |
|---|---|:---:|:---:|
| `USER_EXPERIMENT` | 用户/用户实验室在实物上测得 | ✅ | 机器一致时 ✅ |
| `PUBLIC_REFERENCE_EXPERIMENT` | 他人发表的物理测量 | ✅ | 仅当机器一致 |
| `SIMULATED_REFERENCE` | 模型产生的数据（含本项目合成夹具） | ❌ | ❌ |
| `METHODOLOGY_ONLY` | 只描述试验方法，无可用数值 | ❌ | ❌ |

### 1.1 结构性防火墙

```
EXPERIMENTAL_SOURCE_TYPES = {USER_EXPERIMENT, PUBLIC_REFERENCE_EXPERIMENT}
OWN_MACHINE_SOURCE_TYPES  = {USER_EXPERIMENT}
```

- **唯一判定点**：`is_experimental()`。代码库中禁止任何地方用自己的 `==` 重新判断。
- **重分类单向**：`may_reclassify()` 只允许「向更弱的声明」移动。
  `SIMULATED_REFERENCE → USER_EXPERIMENT` **不存在于允许集合中**，
  也没有任何代码路径能绕过它。
- `EvidenceEntry.__post_init__` 独立再查一次：
  解析层只能带 `NOT_YET_VALIDATED`，有限元层只能带 `NUMERICAL_FEA`，
  而 `EXPERIMENTAL_MEASUREMENT` 标签在非实验来源上**构造即报错**。

> 把仿真洗成测量，是本阶段任何人能做出的最有破坏性的改动。
> 因此该检查在**两个不同模块**中各做一次，并从两个方向被测试。

## 2. 数据集元数据（Step 3）

### 2.1 两种相反的失败

要求完整元数据 → 框架恰好无法接收它存在的理由：
1998 年的论文不会记录测功机操作员，教科书表格没有采集时间戳。
拒绝这类来源，只会逼用户编造数值来满足 schema。

接受静默空白 → 更糟：缺失字段会被读成「测得的 0」或「隐含默认值」。

### 2.2 解法：显式 UNKNOWN

```
必填（仅四项）：dataset_id / title / source_type / test_type
其余全部可选，缺失即 UNKNOWN
```

`UNKNOWN` 是一个**哨兵对象**，不是 `None`：
本代码库中 `None` 已经表示「不适用」或「尚未计算」，
把「论文没写」和「我们没算」混为一谈，正是未知悄悄变成默认值的路径。

`UNKNOWN` 为假值、字符串化为 `"UNKNOWN"`、
在任何视图中都渲染为 `UNKNOWN`，且**永远不是数字**。

### 2.3 字段

| 组 | 字段 |
|---|---|
| 身份 | `dataset_id`, `title`, `source_type`, `test_type`, `schema_version` |
| 机器 | `MachineIdentity`：拓扑/极数/槽数/相数/接法/匝数/额定转速/额定功率/几何备注 |
| 引用 | `Citation`：标题/作者/出处/年份/DOI/URL/页码/表图号/许可/`redistribution` |
| 采集 | `measurement_date`, `operator`, `instrument`, `notes` |
| 溯源 | `raw_file_hash`, `raw_file_name`, `import_timestamp_utc`, `data_provenance` |
| 夹具 | `test_fixture_only`（见 §12） |

## 4. CSV 语义（Step 5）

| 规则 | 反例（本导入器**不会**这么做） |
|---|---|
| 不静默转换 | 逗号分隔文件里的 `12,5` → 报错，**不是** `12` |
| 缺失即缺失 | 空单元格 → `None` 并记入 `missing`，**不是** `0.0` |
| 错误累积 | 一次报出文件中**全部**问题，附行号与列名 |
| 确定性 | 同样字节 → 同样结果，含哈希、行序与错误顺序 |
| 单位有出处 | 表头后缀或调用方声明；**不假设 SI** |

支持：UTF-8（含 BOM）、`#` 与 `//` 注释、空行、缺失标记
（`NA`/`n/a`/`nan`/`null`/`none`/`-`/`--`/`—`）。

行号是**源文件的 1 基行号**，与用户编辑器所见一致——
不是过滤后副本的行号。

## 5. 单位处理（Step 6）

### 5.1 绝不丢失原始表示

```python
NormalizedValue(
    original_value=120.0, original_unit="mNm",
    value=0.12, unit="Nm",
    factor=0.001, provenance="EXACT_SI_PREFIX",
)
```

把 `1800 rpm` 覆盖成 `188.4955592153876 rad/s`，
就丢掉了「有人从显示器上读到 1800」这个事实：
原始读数的舍入没了，把用户自己的数据回显给他的可能性也没了。

### 5.2 转换来源

**全部**为恒等、精确 SI 前缀或成文定义，**没有任何拟合**。
测试逐条断言 `provenance` 只能是这三类之一。

| 量 | 规范单位 | 说明 |
|---|---|---|
| 角速度 | `rpm` | 项目的输入、预设与已发表观测都是 rpm；rad/s 在其旁导出，不取代它 |
| 温度 | `degC` | 项目全部热学输入是摄氏度；转成开尔文只会无谓破坏这些比较 |
| 电阻 | `Ohm` | mΩ/µΩ/kΩ 精确前缀 |
| 转矩 | `Nm` | mNm 精确；kgf·cm 用 g₀ = 9.80665 定义；ozf·in 成文定义 |

温度是唯一的非乘性换算，**显式单独处理**，不被塞进同一个形状。

## 6. 列映射（Step 7）

### 6.1 危险的列叫 `Voltage`

在反电动势台架上，这个表头可能是示波器的线电压有效值、
万用表的相电压有效值，或光标测得的相电压峰值。
三者相差 √3 与 √2 ——极端之间 **73 %** ——
而对同一台机器、同一转速，三种都说得通。

猜错会产生一个**没人看得见**的 Ke 误差，
随后与解析模型的比较会安静地「验证」或「否定」错误的东西。

**因此歧义表头被拒绝**，按名报错，并列出可选目标：

```
[AMBIGUOUS_COLUMN] 第 1 行，列「Voltage」：该列未说明其测量基准，拒绝猜测。
可显式映射为：line_voltage_rms_v、phase_voltage_rms_v、phase_voltage_peak_v。
```

`Current` 同样处理（有效值/峰值/直流不可互换），`Power` 亦然。

### 6.2 显式映射始终优先

```python
column_mapping={"Voltage": "line_voltage_rms_v"}
```

此时有知识的人做出了陈述，而不是启发式在猜。
没有模糊匹配，没有打分。

`RPM`、`Speed`、`Motor Speed (rpm)`、`Shaft Speed` 等
**无歧义**拼写会确定性地解析到 `speed_rpm`。
无法识别的表头被**忽略并记录**，不参与任何分析。

## 7. Ke 工作流（Steps 9-11）

### 7.1 多点回归，而不是单点比值

有多个转速点时，**绝不**只用一个点算 Ke。
拟合 `E = Ke·ω + offset`，报告：

```
斜率 / 截距 / R² / 样本数 / 转速范围 / 残差标准差 / 最大绝对残差 / 最大相对残差
```

### 7.2 截距默认自由

强制过原点是反电动势常数的教科书形式，
也是**掩盖真实测量问题最快的办法**：探头偏置、剩磁、仪器零点。

拟合截距并**报告**它，用户才看得见那个偏置。
强制过零是独立参数，且**必须给出理由**，否则 `RegressionError`。

```python
fit_line(..., force_zero_intercept=True)         # 报错：缺少理由
fit_line(..., force_zero_intercept=True, force_reason_zh="零点已校准")  # 可以
```

截距相对量程超过 2 % 时给出警告，并**明确说明不会把它并入 Ke**。

### 7.3 单点不是拟合

一个测点时斜率是 `y/x`，R² 无定义，关于线性度没有任何证据。
该情形返回 `r_squared = None` 与 `is_single_point = True`，
**不返回 R² = 1.0**——那会是本模块能产出的最具误导性的数字。

### 7.4 排除按行按名

缺转速、缺电压、转速为 0 的行，**逐行记录行号与原因**，
不静默丢弃。

## 8. 电压语义（Step 10）

| 换算 | 因子 | 精确？ | 附带假设 |
|---|---|:---:|---|
| 线 RMS → 相 RMS（Y） | 1/√3 | ✅ | 三相平衡 |
| 线 RMS → 相 RMS（角） | 1 | ✅ | — |
| 相峰值 → 相 RMS | 1/√2 | ❌ | **假设正弦**，非正弦不成立 |

**接法未知时，线/相换算被拒绝**：Y 与角相差 √3，从数字本身无法分辨。

导入文件同时给出线与相电压时，**优先用相电压**——它不需要接法假设——
并明确说明用了哪一列。

## 9. 电阻工作流（Step 12）

| 接法 | 端子读数 → 相电阻 | 依据 |
|---|---|---|
| Y | `/ 2` | 端子间为两相串联 |
| 角 | `× 3/2` | 一相与另两相串联的并联 |
| 未知 | **不给相电阻** | 二者相差 3 倍，此处不猜 |

### 温度归一化绝不自动发生

只有在**同时**满足两个条件时才执行：
调用方显式传入目标温度，且数据中存在测量温度。

结果记录使用的系数：

```
EXPLICIT_REQUEST alpha=0.00393 /K at 20.0 degC (copper, material property)
```

铜的温度系数是**材料属性**，不是拟合值，也不是本项目的标定。
请求了归一化但没有测量温度时，**不作任何修正**，并记录
`REQUESTED_BUT_NO_MEASUREMENT_TEMPERATURE`。

## 10. 转矩-电流工作流（Step 13）

**斜率默认不被称作 Kt。**

每安培的转矩只有在知道「那些安培是什么」时才是转矩常数：
单位功率因数下 q 轴的相有效值是一回事，
驱动器上报的「电流」是另一回事，
跨未知控制策略拟合出的斜率是第三回事。

这些**无法从数字中检测**，因此必须由调用方声明：

```python
analyze_torque_current(rows, current_semantics_known=True, operating_point_known=True)
```

未声明时，`supports_kt_claim = False`，并逐条列出缺失语义。
即使声明了，以下情况仍会降级：

- 拟合截距非零（摩擦/齿槽/测量偏置，不属于电磁转矩常数）
- 测点跨多个转速（斜率是跨工作点的综合结果）
- 用了 `iq` 但未声明 `id` 与控制策略（可能存在磁阻转矩）

## 11. 效率工作流（Step 14）

### 11.1 实测与推导严格分开

```
measured_input_power_w   ← 文件给出的
derived_input_power_w    ← 由母线电压×电流算出的
input_power_source       ← "MEASURED" / "DERIVED_FROM_DC_BUS" / "NONE"
```

**实测功率绝不会被推导值覆盖。**
两者都存在时两者都保留，上报的是实测值——
数据源自己的仪器比本项目的算术更接近真实。

### 11.2 测量边界被明说

输入功率取自直流母线时，测到的是**逆变器 + 电机**的整体效率。
把它当作电机效率上报，会让电机被低估掉逆变器的损耗。
因此 `includes_inverter_losses = True` 并显示边界说明。

效率大于 1 时**标记而不截断**：截断会掩盖功率测量的符号或基准问题。

## 12. 机器一致性（Step 16）

### 12.1 最危险的失败

一条 10 极 12 槽轮毂电机的公开反电动势曲线，
可能与本项目的解析 Ke 吻合到 1 %，
而对当前设计**毫无说明力**。

若软件在旁边显示「实验吻合：1.0 %」，
它就用**完全真实、完全诚实的测量**说了一句假话。
这比一个错误数字更危险——因为它看起来哪里都没错。

### 12.2 四种判定

| 状态 | 含义 | 允许的用途 |
|---|---|---|
| `SAME_MACHINE` | 双方共同声明的决定性参数全部一致 | 可验证当前设计 |
| `COMPATIBLE_REFERENCE` | 决定性参数一致，但匝数/额定点等不同 | 检验建模方法可迁移性 |
| `DIFFERENT_MACHINE` | 至少一项决定性参数冲突 | 仅测试数据管线与方法学 |
| `INSUFFICIENT_METADATA` | 声明不足以判断 | 补齐信息前不得用于任何结论 |

**决定性参数**：拓扑、极数、槽数、相数、接法
**区分性参数**：匝数、额定转速、额定功率、机器编号

`INSUFFICIENT_METADATA` **刻意不乐观**：
未知的机器不会被假定为这一台。
至少需要 2 项决定性参数两边都能对比，才可能给出其他判定。

### 12.3 唯一的验证闸门

```python
def may_validate_current_design(source_type, compatibility) -> bool:
    return is_experimental(source_type) and compatibility is SAME_MACHINE
```

两个条件必须同时成立：数值必须是测量，且必须是**这台机器的**测量。
所有调用方都问这个函数，没有任何地方重新推导。

## 13. 三层比较（Step 15 / 18）

```
ANALYTICAL_MODEL   解析模型     标签固定为 NOT_YET_VALIDATED
NUMERICAL_FEA      数值有限元   标签固定为 NUMERICAL_FEA
EXPERIMENTAL_MEASUREMENT  导入层  标签随数据集来源类别而变
```

前两层的标签是**层的属性**，不是调用方的选择——构造时即校验。
第三层的标签由来源类别决定：
`SIMULATED_REFERENCE` 进入第三列（导入数据都在那里），但标签是 `NUMERICAL_FEA`。

### 结论等级

| `OverallClaim` | 触发条件 |
|---|---|
| `EXPERIMENTALLY_SUPPORTED` | 实验来源 **且** `SAME_MACHINE` |
| `METHODOLOGY_REFERENCE_ONLY` | 实测但非本机器 |
| `SIMULATION_CROSS_CHECK_ONLY` | 来源为仿真 |
| `INSUFFICIENT_METADATA` | 机器识别不足 |
| `NO_EXPERIMENTAL_DATA` | 没有可用实验数据 |

**残差不会升级结论。**
与另一台机器的数据吻合到 0.5 %，报告的是 0.5 %，
**同时**报告「这不验证任何东西」。

## 14. 无数据状态（Step 19）

本项目目前**没有任何物理台架数据**，因此空状态是产品的默认状态，
必须是第一等公民：

```
NO_EXPERIMENTAL_DATA —— 当前项目没有任何实验数据集。
此处不显示 0，也不显示占位测量值，更不会给出「验证通过」。
本项目迄今为止的全部证据仍然是解析模型与数值有限元；
要把任何量提升为「已验证」，必须先导入实测数据。
```

只载入了仿真数据集时，状态**仍然是** `NO_EXPERIMENTAL_DATA`，
并说明「已载入 N 个数据集，但其中没有任何一个是实验测量」。

## 15. 合成夹具政策（Step 21）

测试套件需要测量形态的数据；应用**绝不能**把它显示为测量。
这两个要求直接冲突，解法是结构而非命名约定：

1. 全部夹具只能由 `synthetic_dataset()` 构造，**它没有 `source_type` 参数**
   （硬编码 `SIMULATED_REFERENCE`）；
2. `DatasetMetadata.__post_init__` **独立**拒绝任何声称非仿真的夹具；
3. `test_fixture_only=True`，`require_production_admissible()` 在生产边界拒绝；
4. 标题带 `[TEST FIXTURE — NOT A MEASUREMENT]` 前缀；
5. 数值由**成文闭式表达式**生成，测试断言精确值而非噪声容差。

`ValidationDataService.add_*` 在入口调用防火墙，
`production_datasets()` 过滤夹具。测试从两个方向断言。

## 16. 项目持久化（Step 22）

### 16.1 三个选项与取舍

| 方案 | 优点 | 致命问题 |
|---|---|---|
| 样本嵌入 `.motorproj` | 完全自包含 | 5000 点效率图会淹没一个几 KB 的项目文件；导入受版权保护的表格会把它嵌进项目的每一份拷贝 |
| 引用用户原始路径 | 零膨胀 | 文件一移动就失效，且无法判断文件是否还是导入时那份 |
| **复制进应用数据目录并引用** | **采用** | — |

### 16.2 采用方案

- 数据按**内容哈希寻址**存入应用数据目录（同一份数据导入两次只存一份）；
- 项目只存**小引用**：id、元数据、哈希、列映射、比较配置；
- 手工录入的数据集**内联**保存在项目里（体积小，且没有文件可指）。

### 16.3 与 Phase 10H 同样的不迁移策略

键放在已有的 `ui_preferences` 扁平标量映射中，前缀 `experiment.`，
**`PROJECT_SCHEMA_VERSION` 不动**，
本阶段之前写出的每一个项目文件都逐字节照常载入。

### 16.4 缺失与改动

| 状态 | 行为 |
|---|---|
| `AVAILABLE` | 文件存在且哈希一致 |
| `MISSING` | **元数据完整保留**（元数据正是说明「丢的是什么」的东西），不参与比较，不补零 |
| `CHANGED` | 文件在，哈希不符：**已被改动**，重新导入确认前不参与比较 |
| `INLINE` | 手工录入，存于项目内 |

缺失文件**从不抛异常**。

## 17. 导出（Step 23）

导出的报告比它来自的屏幕活得久：会被贴进设计评审、附在邮件里，
或一年后被不在场的人读到。
界面用排版与颜色传达的一切，**必须以文本形式存活**，
否则导出就是那些谨慎区分被丢失的地方。

### 唯一的禁令

`VALIDATED` 一词**只能**用于本机器的实验测量。

```python
CLAIM_TEXT = {
    EXPERIMENTALLY_SUPPORTED:     "EXPERIMENTALLY_SUPPORTED",
    METHODOLOGY_REFERENCE_ONLY:   "NOT_VALIDATED / METHODOLOGY_REFERENCE_ONLY",
    SIMULATION_CROSS_CHECK_ONLY:  "NOT_VALIDATED / SIMULATION_CROSS_CHECK_ONLY",
    NO_EXPERIMENTAL_DATA:         "NOT_VALIDATED / NO_EXPERIMENTAL_DATA",
    INSUFFICIENT_METADATA:        "NOT_VALIDATED / INSUFFICIENT_METADATA",
}
```

`_claim_text()` 是唯一能输出该词的地方，并带一条防御性断言，
防止未来的编辑把它塞进非肯定性结论。
测试断言：不同机器的数据集，其报告中 `VALIDATED` 的每一次出现前四个字符都是 `NOT_`。

**局限不是脚注，是必需章节**：没有局限章节的报告被视为缺陷，而不是「一切正常」。

导出内容：数据来源、来源类别及其告诫、引用（DOI/URL/页码/表图号/许可/再分发）、
机器一致性及理由与允许用途、测试类型、样本数、回归指标、
解析值、有限元值、实验/参考值、残差、局限、标定状态。

另提供**仅元数据导出**（`export_dataset_metadata`），
用于再分发许可未知或不允许的来源。

## 19. 一次计算，两个视图

Phase 10G/10H 把绕组报告、槽利用率、生产权威与可制造性问题
分成四个调用，唯一组装它们的地方是绕组对话框——
**在一个 Tk 控件内部，读它自己的 `StringVar` 假设字段**。

仪表板要显示同一件事的浓缩版。
再组装一遍会为「用户在两处看到的同一个数字」制造两个真相来源，
而它们一定会漂移。

因此组装逻辑移入 `winding/evaluation.py`：
对话框成为一个调用方，仪表板成为另一个，**两者都不额外计算任何东西**。
Phase 10H 的防火墙原样适用：剖分 FEA 绕组系数可以**传入用于并列显示**，
永远不会成为生产值。

## 20. Phase 10 遗留项关闭（Steps 1-2）

### 20.1 File → New

Phase 10H 写了 `new_project_state()` 并为它写了测试，
但**从未给它生产消费者**。
`File → New` 创建的文档不携带任何绕组键——
而这恰好是 `from_preferences` 读作「该项目早于这套语义」的信号——
于是**每一个全新项目都被判为 `LEGACY_MANUAL`**，
同时出厂启动示例却是 `AUTO`。

**新文档什么都不说**和**旧文件什么都不说**不是同一句话，这就是整个缺陷。

修复放在**创建**一侧：

```python
def _new_project_ui_preferences(self) -> dict:
    return dict(new_project_ui_preferences(
        slots=..., pole_pairs=..., coil_span_slots=..., manual_winding_factor=...,
    ))
```

**载入路径完全未动**：说不出话的既有文件仍然是 legacy。
几何不足以推导时**不发明绕组系数**：保留手动值，模式保持 manual。

GUI 冒烟先把会话**强制设为 MANUAL**，再执行 File → New，
因此之后出现的 AUTO 只可能来自新建路径本身。

## 21. 局限

- **仍然没有任何物理台架数据。** 本阶段没有引入一条真实实验测量。
- 公开文献**尚未接入**：只准备了架构，没有抓取、没有虚构示例数据。
- 读图数字化的不确定度**尚未量化**——这是 Phase 11B 的硬性前置条件，
  因为读图误差与本项目试图解释的 7 % 级残差量级相当。
- 效率比较的边界差异（逆变器 vs 电机）被**说明**，但尚未建模扣除。
- 转矩-电流不会自动成为 Kt 验证；这是设计意图，不是待办。
- `INDUCTANCE`/`THERMAL`/`TORQUE_SPEED`/`NO_LOAD_CURRENT`/`LOSS_MAP`
  可导入可保存，但没有分析。
- 尚未构建或发布任何正式发行版；Phase 10 栈仍未合并。

## 22. Phase 11B 计划：公开参考数据接入

`public_reference.PHASE_11B_REQUIREMENTS` 中记录了硬性要求
（写在代码旁而不只写在文档里，以便要求与将来必须满足它的代码同处一地）：

1. **可提交的来源清单**：每条含 DOI/URL、页码、表号或图号、许可状态，
   且**不含任何原始测量值**。
2. **「元数据先行」导入流程**：先登记 `PublicSourceRecord`，
   再由使用者提供数据文件，导入时用已登记的列映射，不做任何猜测。
3. **读图数字化不确定度模型**：`FIGURE_DIGITISATION` 必须携带可量化的读数误差。
4. **机器识别最低门槛**：公开来源常缺槽数或接法，
   需明确缺多少项时判 `INSUFFICIENT_METADATA` 而非 `COMPATIBLE_REFERENCE`。
5. **同机器多来源交叉核对**：两篇独立测量若彼此矛盾，
   软件必须**显示矛盾**，而不是取平均。
6. **术语归一化**：不同文献对 Ke 的定义（线/相、有效值/峰值、机械/电气角速度）
   差异巨大，需在导入时强制声明，而不是在比较时假设。
7. **可审计的政策文档**：说明哪些来源已被检视、哪些被排除及原因，
   使「没有引用某篇文献」是一个决定而不是遗漏。

### 版权立场

`redistribution = UNKNOWN` **按不允许处理**。
许可不明确不等于获得许可，「许可不清楚」也不是抗辩理由。
首选产物是**导入器 + 元数据**：提交引用、页码、表号与列映射，
数值由具备合法访问权限的使用者自行提供。
