## 2. P0-1：legacy K_fill 的可制造性结论

### 2.1 复现结果

`legacy K_fill = (3·N_ph·2·n_par·d_wire) / (π·D_in)` 是**内圆周上的一维裸铜线宽占比**，
不是槽铜面积/槽面积之比。实测：

| 设计 | legacy K_fill | Phase 8G 近似裸铜槽占比 |
|---|---:|---:|
| application default（无铁芯） | **2.4555** | `NOT_ENOUGH_GEOMETRY` |
| 可制造性起始示例 | **3.2740** | **0.3177** |
| 故意设计的劣质槽型 | **9.8221** | **0.9531** |

决定性证据：**把槽深加倍，Phase 8G 占比下降，而 legacy K_fill 逐位不变**——
该指标完全不响应槽几何，因此在任何意义上都不是槽满率。

legacy 基类 `_check_design_validity`（`PMDC_Calculator_claude204.py:1482`）的
`K_fill > 0.8 → "严重：填充系数超过实际限制 - 无法制造!"` 对上述三个设计**全部命中**，
包括 Phase 8G 判定为可行的起始示例。

### 2.2 对 RC1 评审的更正

**RC1 报告将该告警列为 confirmed defect D-02，属于高估。**

MRO 实测：

```
MRO: _RealMotorCalculatorApp -> MotorCalculatorAppMixin -> MotorCalculatorApp(legacy) -> object
_check_design_validity 解析到: MotorCalculatorAppMixin  (gui/main_window.py)
```

`MotorCalculatorAppMixin._check_design_validity` **早已覆盖** legacy 实现并委派给
`validation.design_feasibility`。因此该 legacy 文案在实际应用中**不可达**。
RC1 定位了 legacy 代码但未验证 MRO。同样的更正适用于 D-03 中"增加匝数"提示的部分。

**真正在线的是 `run_optimization`**——它没有被覆盖，解析到 legacy 实现。

### 2.3 修正内容

| 位置 | 修正 |

## 3. P0-2：电压基准不一致

### 3.1 复现结果

`required_voltage_v` 是**线电压 RMS** 需求。legacy 把它直接与**直流母线电压 Vdc** 相比：

```
legacy margin = (Vdc − V_required) / Vdc
```

Phase 6F/8G 已确立同基包络为线性 SVPWM 的 `Vdc/√2`。可制造性起始示例（Vdc=72 V）：

```
legacy 直流母线差额 = +40.3382 %   → 触发 legacy "考虑增加匝数"
同基电压裕量        = +15.6255 %   （可用 50.9117 V / 所需 42.9565 V）
```

且**按提示增加 10 匝后，同基裕量进一步下降**——测试已断言该方向性。

### 3.2 优化器行为 before / after

优化器约束是**真正在线**的缺陷。以可制造性起始示例扫描 `N_ph_turns ∈ [15, 120)`：

| 判据 | 接受区间 | 候选数 |
|---|---|---:|
| legacy `V_required ≤ Vdc` | `15..81` | 23 |
| 同基 `V_required ≤ Vdc/√2` | `15..57` | 15 |

**legacy 判据误接受 8 个候选**：`N = 60, 63, 66, 69, 72, 75, 78, 81`。

此外，软目标 `target_V = 0.85·Vdc = 61.2 V` **本身就超出包络 50.91 V 约 20%**，
即优化器在主动朝不可实现的方向优化。

### 3.3 修正内容

在 `validation/design_feasibility.py` 中新增唯一权威 API：

```python
SVPWM_LINE_RMS_ENVELOPE_RATIO = 1/√2
same_basis_available_line_rms_v(dc_bus_voltage_v)
same_basis_voltage_margin_percent(dc_bus_voltage_v, required_line_rms_v)
```

`_voltage_margin` 改为调用它们（**数值完全等价，无行为变化**）。优化器三处改为同基口径：

| 项 | 修正前 | 修正后 |
|---|---|---|
| 硬约束 | `V_required > Vdc` | `V_required > Vdc/√2` |
| 电压利用率目标 | `0.85·Vdc` | `0.85 ×` 同基可用线电压 RMS |
| 摘要标签 | `电压裕量`（legacy 值） | `同基电压裕量` + 显式标注的 legacy 值 |

**RC2 优化器对起始示例的推荐**：

```
N_ph_turns = 51, n_parallel = 2
所需线电压 RMS = 43.8150 V
同基电压裕量   = +13.9393 %
近似裸铜槽占比 = 0.3240   (legacy K_fill = 3.3395)
电流密度       = 4.2548 A/mm²   效率 = 89.5156 %
```

## 4. 槽满率可见性（用户需求："槽满率要表示出来"）

### 4.1 术语

统一采用 **`近似裸铜槽占比`**。

**不使用** `真实槽满率` / `制造槽满率`，因为模型只计算裸铜截面积占可用槽面积之比，
未包含导线绝缘、槽绝缘、排布与绕制工艺。

计算口径（Phase 8G，未改动）：

```
毛槽面积   = (w_top + w_bottom)/2 × h_slot
可用槽面积 = 毛槽面积 − w_top × h_wedge          （显式扣除槽楔）
铜面积     = 3 × 2 × N_ph × n_parallel × π(d/2)²
占比       = 铜面积 / (槽数 × 可用槽面积)
```

### 4.2 展示位置

| 位置 | 状态 |
|---|---|
| 结果仪表板 KPI 卡 + 量程条 | 已有（Phase 8H） |
| **详细工程报告顶部摘要** | **RC2 新增** |
| **优化器结果摘要** | **RC2 新增** |
| **TXT 完整导出** | **RC2 新增** |
| **JSON / CSV 导出** | **RC2 新增**（见 §5） |
| 速度扫描 CSV | 已有（同基电压列） |

显示形式：值 + 百分比 + 可用性状态 + 工程解释。例如

```
近似裸铜槽占比        : 0.3177 (31.8 %)
```

槽几何不足时显示 `信息不足（NOT_ENOUGH_GEOMETRY）`，**绝不用 legacy K_fill 顶替**。

### 4.3 指导带

沿用 Phase 8G 语义，未新增"通用制造定律"：

| 区间 | 级别 |
|---|---|
| > 0.80 | 严重设计风险 |
| 0.60 – 0.80 | 警告 |
| 0.50 – 0.60 | 审慎复核 |

所有消息均声明实际可制造性还取决于导线绝缘、槽衬、绕线工艺、圆线/扁线、绕线张力、
嵌线方式、浸漆与槽形。

## 6. 绕组系数 Auto / Manual 架构（用户问题："绕组系数不是计算出来的吗？"）

### 6.1 修改前的实际状态（审计结果）

- `k_w` 在 production 路径中**永远是手工输入**（`input_ux/metadata.py` 默认 0.93，
  滑块 0.50–1.00 步长 0.005）。
- 存储于 presets（`presets.json`）与 project schema v1（`schema.py:81`，
  分组 `winding`，语义 `winding_factor`）。
- **代码库中没有任何地方计算它。**
- `advanced_afpm/winding_network.py:resolve_winding_factor()` 只做两件事：
  直接返回给定的 `kw`，或在 `kp` 与 `kd` **都显式给出**时返回 `kp × kd`；
  否则返回 `UNAVAILABLE`，注释明确写着
  *"Geometry or winding type alone is insufficient to invent kw."*
- 消费者：`calculations.py` 的反电动势计算（PMSM 与 BLDC 两个分支）与波形峰值。
- **没有任何谐波绕组系数**（`k_w5` / `k_w7` 此前不存在）。

**结论：用户的质疑成立。**

### 6.2 现有 schema 是否足以自动计算？

| 量 | 是否已有 | 说明 |
|---|---|---|
| 槽数 Q | ✅ `slots` | |
| 极对数 p | ✅ `p` | |
| 相数 m | ✅ 模型固定为 3 | |
| q = Q/(2p·m) | ✅ 可推导 | **允许为分数** |
| 槽距电角度 | ✅ 可推导 | `2πp/Q` |
| **线圈节距** | ❌ **缺失** | 新增显式可选输入 |
| **斜槽量** | ❌ **缺失** | 新增显式可选输入 |

因此 `k_d` **今天就能算**；`k_p` 必须新增输入。
**整距不是几何必然结果，而是设计选择，因此绝不自动假设。**

### 6.3 算法

新模块 `motor_core/winding_factor.py`（GUI 无关，不含任何 legacy 因子）：

```
k_w1 = k_d1 · k_p1 · k_s1
```

- **k_d（分布系数）**：由**槽电势星形图**（star of slots，Bianchi/Dai Pré）直接求得。
  每槽 EMF 相量角 `θ_k = k·2πp/Q`；A 相占据以 0° 为中心的相带（正向串联）与
  以 180° 为中心的相带（反向串联），相带宽度 `180°/m`。
  `k_d = |Σ sign_k·e^{jθ_k}| / N_A`。
  **该方法对整数 q 与分数 q 使用同一条代码路径**，这是分数槽集中绕组的必要条件。

  相带分配采用**精确整数运算**：`belt = ((r·4m + Q) // (2Q)) mod 2m`，其中 `r = (k·p) mod Q`。
  改用浮点判边界会让恰好落在相带边界上的相量随舍入方向漂移，
  从而**静默地**把 Q=24 / 2p=4 这类整数槽绕组判成不对称。

- **k_p（节距系数）**：`|sin(n·γ/2)|`，`γ = 节距槽数 × 槽距电角度`。
- **k_s（偏斜系数）**：`|sin(x)/x|`，`x = n·σ/2`，`σ = 斜槽槽距数 × 槽距电角度`；无偏斜时恒为 1.000。

**平衡性判据**：要求每相线圈边数相等（`Q mod m == 0` 且三相各得 `Q/m`）。
不使用"每相带等数"判据——分数槽绕组（如 Q=9 / 2p=8）各相带本就不等，
但每相总数相等，仍是合法的对称绕组。

不平衡组合（Q=10/2p=8、14/10、8/6、20/8、11/10）**抛出异常**而非返回近似值。

### 6.4 参考算例（手算核对，STEP 24）

**参考 A — 经典整数槽分布绕组**

```
Q = 24, 2p = 4 (p = 2), m = 3
槽距电角度 α = 2πp/Q = 30°
q = Q/(2p·m) = 2          （整数）
整距 = Q/(2p) = 6 槽
线圈节距 = 5 槽（5/6 短距，150° 电角度）
k_d1 = sin(q·α/2)/(q·sin(α/2)) = sin30°/(2·sin15°) = 0.9659258263
k_p1 = sin(150°/2) = sin75°                        = 0.9659258263
k_s1 = 1.000000                                     （无偏斜）
k_w1 = 0.9330127019
```

**参考 B — 分数槽集中绕组（齿绕）**

```
Q = 12, 2p = 10 (p = 5), α = 150°, q = 0.4, 节距 = 1 槽
k_d1 = 0.9659258263, k_p1 = sin75° = 0.9659258263
k_w1 = 0.9330127019        （12 槽 10 极的标准值）
```

**参考 C**：`Q = 9, 2p = 8, 节距 1 槽` → `k_w1 = 0.945214`（9 槽 8 极标准值）
**参考 D**：`Q = 12, 2p = 14, 节距 1 槽` → `k_w1 = 0.9330127`

**闭式解交叉验证**：对所有整数 q 的组合（24/4、36/6、48/8、24/8、36/4、72/12），
星形图结果与 `sin(q·α/2)/(q·sin(α/2))` 的误差 **< 1e-12**。

### 6.9 一个值得注意的工程发现

application default 的实际拓扑为 `Q=24, 2p=16 → q=0.5`（分数槽齿绕），
齿绕节距必为 1 槽。此时：

```
k_d = 1.0000,  k_p = sin(60°) = 0.8660,  k_w1 = 0.8660
```

而默认手填值为 **0.93**。也就是说，**默认值对其自身拓扑偏乐观约 7.4%**。

RC2 **不自动改写**该默认值——它是冻结的 legacy 输入。用户可切到自动模式
并显式给出节距来获得几何一致的值。

## 7. 首次启动策略（STEP 19）

修改前，首次启动同时触发三项：

```
电流密度 J = 8.88 A/mm²      → CURRENT_DENSITY_HIGH
同基电压裕量 = −51.79 %       → VOLTAGE_MARGIN_SEVERE
legacy 绕组占比 = 2.4555      → legacy 恒真"无法制造"
```

新用户无法区分"我的设计有问题"与"这个软件坏了"。

RC2 让 GUI 首次启动加载 **`design.manufacturability_start.v1`（可制造性起始示例）**。

## 8. 中文工程说明文案（STEP 21）

- **槽占比**：当前值表示槽内裸铜导体截面积与有效槽面积的近似比值。实际制造槽满率还受绝缘、排布和绕制工艺影响。
- **绕组系数**：绕组系数反映绕组分布、线圈节距和偏斜等因素对基波电势/磁动势的影响。若当前模型具有完整绕组几何，则自动计算；否则可由用户手动提供。自动模式需要槽数、极对数和线圈节距三项同时可用。
- **线圈节距**：以跨过的槽数表示。整距对应 Q/(2p) 槽。整距不是几何必然结果，因此不会被自动假设；留空则退回手动指定模式。
- **斜槽**：以槽距为单位。0 表示未建模偏斜，此时 k_s = 1.000。
- **电压裕量**：该裕量使用统一的 line-RMS 电压基准比较，不等同于完整逆变器瞬态动态裕量。

## 10. 遗留限制（明确记录，未修复）

以下项**位于受保护的 `motor_core/calculations.py` 内**，按安全规则未做修改，
需要显式批准：

1. **气隙磁密谐波频谱横轴方向反了**（`calculations.py:490`）。
   `harmonics = k × pole_pairs` 应为 `k / pole_pairs`；下游 `harmonics ≤ 25`
   把基波过滤出图。显示层缺陷，不影响任何数值结果。
2. **`required_voltage_v` 基准混用**：`R` 用线基准 `2R_ph`，`X` 用每相同步基准
   `1.15 L_ph`（`line_inductance_h` 实为同步电感，命名误导）。
3. **`required_voltage_v` 用三项 RSS 而非相量合成**，比 `√((E+IR)²+(IX)²)` 低约 3.89%，方向非保守。
4. **`coreless=True` 仍计入铁损** `0.01·P_rated`（默认设计 8 W，占总损耗 11.4%）；
   `is_coreless` 在齿槽转矩处被查询，在铁损处未被查询。
5. **齿槽波形 360 点采样**在 `3·LCM(2p, Q) > 179.5` 时混叠（如 2p=20 / Q=30）。
6. **铜导体涡流损耗**以气隙峰值磁密覆盖全部铜体积（含端部绕组），系统性高估。

其余 RC2 未处理项见 `docs/reviews/legacy_surface_inventory_zh.md` §4，包括
`fill_limit` 输入标签仍沿用"填充系数限制"旧词。

模型能力矩阵与既有限制（AFPM 外部验证有限、参数不确定性 ≠ 总预测误差、
静态热保真度有限、速度扫描不是能力包络、BLDC 开关侧电压语义不足、
动态模型为工程沙盒等）**在 RC2 中未发生变化**。
