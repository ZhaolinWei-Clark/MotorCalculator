## 6. 反电动势波形处理

### 6.1 为什么需要一个新测试类型

Phase 11A 的 `NO_LOAD_BACK_EMF` 是「多个转速点 vs 电压」，用于拟合斜率。
CREATOR 给的是「**单一转速下的角度域波形**」。

二者是不同的问题。把后者套进前者，会让一个单点比值**借用回归的地位**。
因此新增：

```
BACK_EMF_WAVEFORM   角度/时间域波形，单一已知转速
NO_LOAD_BACK_EMF    多转速点，回归（Phase 11A，未改动）
```

### 6.2 为什么是适配器而不是列映射

Phase 11B-A 审计中验证过：把 `Rotor angle` 映射到 `speed_rpm`，
Phase 11A 的导入器会返回 `ok=True` —— **而结果毫无意义**。

所以本阶段**完全不走列映射路线**。每个适配器自行声明它期待的布局、校验之，
并产出一个**语义写在类型里**的结果对象。

### 6.3 声明的语义

```
文件        : Measurement_results/No_load_tests/Back_emf.csv
角度基准    : MECHANICAL_DEGREES          （机械度，0–360）
电压基准    : PHASE_TO_NEUTRAL_INSTANTANEOUS
转速        : 2000 rpm    ← 来自来源文档，单一转速的记录无法自证其转速
极对数      : 2           ← 同上
```

**平衡性校验**：`max|Eu+Ev+Ew| = 1.281 V`，为原始峰值的 **1.97 %**，
在 2 % 容差内 → 确认这三列确实是相对中性点的相电压。

## 7. 谐波提取

### 方法（写清楚才可被检验）

样本对**角度**而非时间采样，且步长不完全均匀（0.040–0.050 机械度）。
直接 FFT 需要重采样，等于把一个插值选择塞进本应是观测的结果里。

因此采用**直接数值投影**：

```
a_k = (2/Θ) · Σ y_i · cos(k·p·θ_i) · dθ_i
b_k = (2/Θ) · Σ y_i · sin(k·p·θ_i) · dθ_i
A_k = √(a_k² + b_k²)
```

- `θ` 为机械角（弧度），`p` 为极对数 → `k=1` 即**电气基波**
- `Θ` 为**实际积分跨度**，不是假定的 2π：文件覆盖 360.0076° 就按 360.0076° 归一化
- **不加窗**：记录跨整数个周期，加窗只会衰减待测分量

**`A_k` 是峰值**，不是有效值、不是峰峰值。正弦分量的有效值 = `A_k/√2`。
之所以写明，是因为让反电动势常数错 41 % 的最常见方式，
就是自己对这三者含糊其辞。

### 提取结果（U 相）

| 量 | 数值 |
|---|---:|
| 基波峰值 h1 | **47.386787 V** |
| 基波有效值 | 33.507519 V |
| 原始波形峰值 | 64.9750 V |
| **原始峰值 / 基波峰值** | **1.3712** |
| THD（2–13 次） | 20.623 % |

| 谐波 | 峰值 | 占基波 |
|---|---:|---:|
| h5 | 6.253584 V | 13.197 % |
| h7 | 6.629244 V | 13.990 % |
| h11 | 3.369367 V | 7.110 % |
| h13 | 1.014960 V | 2.142 % |
| h3 | 0.177248 V | 0.374 % |
| h2 / h4 / h6 | < 0.18 V | < 0.4 %（偶次可忽略，符合对称机器预期） |

**波形显著非正弦。** 直接把原始峰值 64.98 V 当作基波会**高估 37.1 %**。
这正是必须提取而不能直读的原因。

三相基波离散度 **0.1999 %**（U 47.3868 / V 47.4816 / W 47.4400）。

## 8. 47.37 V 的复现

```
提取值 : 47.386787 V
公开值 : 47.37 V
偏差   : +0.03544 %
容差   : ±0.05 %
复现   : 是
```

### 容差如何定

公开值只印到 4 位有效数字（47.37 V），因此只能断言到最后一位：
±0.005 V 即该位的半个单位，0.05 % 略有余量地覆盖它，
同时仍然紧到足以暴露真实错误。

### 没有任何调参

`harmonics.py` **完全不知道** 47.37 这个数（测试断言该文件中不含此字符串）。
比对发生在提取**之后**，在 `check_against_publication()` 中；
波形分析函数从不接收公开值。测试同样断言了这一点。

**若提取结果超出容差，失败的是本软件，不是来源数据。**

### 一个应当说明的敏感性

Phase 11B-A 审计脚本得到 47.3762 V，本适配器得到 47.3868 V，相差 0.022 %。
差异来自**末样本的积分权重**：审计只用了 N−1 个区间，
适配器为最后一个样本补上平均步长，以免记录被悄悄截断。
两者都在公开值容差之内，此处如实记录这一方法敏感性。

## 9. 单转速 Ke 语义

只有一个测点，因此**不走多转速回归路径**。

```
Ke = 0.11312762 V/(rad/s)

provenance   : MEASUREMENT_DERIVED_SINGLE_SPEED
电压基准     : PHASE_PEAK
转速基准     : ELECTRICAL_RAD_PER_S
转速         : 2000 rpm  (ω_e = 418.8790 rad/s)
公式         : Ke = E1_phase_peak / ω_electrical
R²           : 不适用
不确定度     : NOT_QUANTIFIED
```

### 为什么**没有** R²

R² 描述一条直线对若干点的拟合优度。只有一个工作点时，
没有直线、没有残差、没有可描述的对象。
给出 R² 会让一个单纯的比值**看起来像拟合结果**，
而这正是该类型存在的意义所在。

`SingleSpeedKe.r_squared` 属性存在且恒为 `None`，
这样即使调用方按多转速结果的形状去取，得到的也是**显式的缺席**而不是 `AttributeError`。

基准改变会改变数值，且每次都写明：

| 电压基准 | 转速基准 | Ke |
|---|---|---:|
| PHASE_PEAK | ELECTRICAL | 0.11312762 |
| PHASE_PEAK | MECHANICAL | 0.22625524 |
| PHASE_RMS | ELECTRICAL | 0.07999331 |
| PHASE_RMS | MECHANICAL | 0.15998662 |

## 15. 行驶工况摄取

只实现了读取 CREATOR 文件所必需的部分，**没有**建设庞大的工况子系统。

### 已处理的来源不一致

| 车型 | 表头 |
|---|---|
| `Small_sized_vehicle` | **有**（`Time,Power`） |
| `Mid_sized_vehicle` | **无** —— 首行即数据 |

差异是**按文件夹**声明在 `COLUMN_LAYOUTS` 中的，**不做嗅探**。
若按有表头读取无表头文件，首个样本会被当作表头吞掉（3601 → 3600）。
测试断言两者都得到 **3601** 行。

### 功率语义来自文件名，不来自表头

小型车文件的表头是裸的 `Power`，它**不说明**是输入还是输出。
Phase 11A 的通用导入器正确地拒绝了这一列。
本适配器从**文件名**取语义：

```
*_input_power.csv   → input_power_w    DC_INPUT
*_output_power.csv  → output_power_w   MECHANICAL_OUTPUT
*_speed_rpm.csv     → speed_rpm        MECHANICAL_RPM
*_torque_nm.csv     → torque_nm        MOTOR_SHAFT
```

### 回馈功率

负功率表示回馈（发电）运行，**按原样保留，不取绝对值、不截断**。
WLTP / 小型车：3601 点中有 **934** 个回馈样本，输出功率最低 −8.6685 W。

循环效率取**能量之比**（输出能量 / 输入能量 = 0.5654），
而非逐点效率——存在负功率时逐点效率没有意义。

转矩与转速来自车辆纵向模型的下调结果，属**计算输入**而非测量。

**不写入项目文件**：否则会把一个机器相关的绝对路径带进每一份项目拷贝。

## 18. 局限

- **本项目仍然没有任何自有物理台架数据。**
- CREATOR 数据中**完全没有电流测量**，因此无法支撑 `TORQUE_CURRENT`。

## 19. 为什么 CREATOR 不验证当前 AFPM 设计

**两个独立的理由，任一成立即足够。**

### 19.1 机器不同

极数 4 vs 16、槽数 6 vs 24、拓扑径向 vs 轴向。
`may_validate_current_design()` 返回 `False`，与残差大小无关。

### 19.2 生产内核根本无法表示它

`motor_core/calculations.py` 开篇即 *"Pure calculation kernel for the AFPM
PMSM/BLDC model"*，其输入按构造就是轴向的：
`D_out`/`D_in` 描述圆环，`g_side` 是双转子结构的**单侧轴向**气隙，
`h_coil`/`h_yoke`/`L_magnet` 沿轴向度量。

CREATOR 是径向磁通嵌入式机器（定子内径 47.8 mm、转子外径 47 mm、
**径向**气隙 0.4 mm、叠长 30.1 mm）。
**不存在**一种把这些尺寸装进 AFPM 字段而仍然保持物理意义的映射。

这样建出来的项目会正常运行、产出看似合理的数字，**而毫无意义**——
这比报错更糟，因为它**看起来像一个结果**。

因此该不匹配被做成**结构性**的：

```python
require_compatible_topology(RADIAL_FLUX_INSET_PMSM)   → TopologyMismatchError
reject_afpm_project_construction(CREATOR_MACHINE.topology) → TopologyMismatchError
```

`TopologyMismatchError` 刻意继承 `TypeError`：这是**范畴错误**，不是取值错误。
调多少参数都不会让径向机器变成轴向机器。

### 19.3 成功导入到底证明了什么

```
PUBLIC_REFERENCE_PIPELINE_VALIDATED      ← 本次获得
CURRENT_AFPM_NOT_EXPERIMENTALLY_VALIDATED ← 恒定不变
```

成功复现公开实测数据，验证的是**本软件的数据处理链**：
解析、单位、语义、波形处理与证据分级。
它**不验证**当前 AFPM 设计本身。

测试断言：即使公开值被完美复现，`afpm_claim` 也不移动。

## 20. Phase 11B.2 建议

按价值排序：

1. **解决 λ_pm 与齿槽标量两项来源歧义** —— 联系来源作者
   （pawan.dhakal@tugraz.at，README 中公开）。这是两条具体、可回答的问题，
   而不是开放式研究。解决后，CREATOR 参数表将成为一份**完全无歧义**的公开参考。

2. **CREATOR 感应电机数据集**（DOI `10.3217/kh3v7-dhn98`）——
   同一课题组、同样格式、同样许可。本阶段的适配器骨架可直接复用，
   且能检验本软件在**另一种拓扑**上的语义处理。

3. **HardwareX BLDC**（Zenodo `10.5281/zenodo.20035899`）——
   需要先做一个明确决定：是否下载外部数据。
   它带来本项目目前完全缺失的东西：**完整的不确定度分析**
   （扩展不确定度 0.428 % k=2、电流偏置 +0.93~1.20 %、速度响应 RMSE 14.8 rpm）。
   注意其电流是 **DC 母线电流**，绝不可直接映射为相电流。

4. **不确定度框架** —— 目前所有导入数据都没有误差条。
   在引入 HardwareX 之前先建立这一层，否则其最有价值的部分无处安放。

### 不建议现在做

- 为 CREATOR 建立 AFPM 项目（§19，拓扑上不可能）
- 径向磁通生产模型（改动量巨大，且会触及受保护物理）
- 通用文献导入系统（证据尚不要求）
