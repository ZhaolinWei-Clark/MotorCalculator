# 待决策事项

更新时间：2026-07-02

## 1. 第三阶段前的总目标

第三阶段开始前，应先把所有“结构性修改”和“会改变结果的修改”彻底分开。

当前推荐目标：

- 保持现有 baseline 稳定
- 在动公式前列出全部待批准项
- 先确认语义，再改实现

## 2. 待确认的关键公式问题

### 2.1 `Kt` / `Ke` 语义

待确认内容：

- `Kt` 当前实现对应的是相电流还是线电流
- 是 RMS 还是 peak
- PMSM 与 BLDC 是否应共用同一套常数关系
- 与 `E_phase_rms`、`E_line_rms` 的关系是否符合目标驱动方式

影响：

- 额定电流
- 转矩常数
- 电压需求
- 铜损
- 效率

### 2.2 `9.55 * P / n`

待确认内容：

- 是否继续保留 legacy rpm 形式
- 是否在获得批准后替换为严格 SI 角速度表达

影响：

- 额定转矩
- 额定电流
- 所有下游损耗与效率

### 2.3 所需电压模型

待确认内容：

- 当前 `sqrt(E^2 + (IR)^2 + (ωLI)^2) * margin` 是否继续保留
- 是否需要区分控制策略、相位角和逆变器调制度

影响：

- 电压裕量
- 设计可行性判断
- 优化方向

### 2.4 `K_fill`

待确认内容：

- 当前 legacy 定义是否只作为占比代理量保留
- 是否将来替换为真实槽满率模型

影响：

- 制造性判断
- 设计约束真实性

### 2.5 经验损耗模型

待确认内容：

- 铁损比例模型是否继续保留
- 机械损耗与风阻损耗是否需要按拓扑细化
- 涡流损耗经验式是否需要限定适用范围

影响：

- 输入功率
- 效率
- 热设计判断

- 还未完全摆脱对 `PMDC_Calculator_claude204.py` 的界面依赖

## 4. baseline 相关风险

- `legacy_baseline.json` 只覆盖了 3 组案例
- 它能防止明显回归，但不能覆盖所有输入边界
- 后续如引入公式修改，必须先决定是：
  - 保留旧 baseline 作为 legacy 对照
  - 还是在批准后新增下一代 baseline

## 5. 下一阶段建议顺序

建议顺序：

1. 列出全部“可能改变结果”的公式与语义项
2. 逐条说明当前定义、问题和影响
3. 等待批准
4. 批准后再分批修改
5. 每批修改后生成差异报告

## 6. 修改公式前必须获得批准的规则

任何下列操作都必须先获得批准：

- 修改公式常数
- 修改单位语义并影响结果
- 修改相值/线值定义
- 修改峰值/有效值定义
- 修改双气隙/双转子系数
- 修改损耗模型
- 修改 baseline 数据

## 7. 当前不应做的事

- 不要把 legacy baseline 宣称为物理正确值
- 不要为了让测试通过而重写 baseline
- 不要在未批准时重构出“新物理模型”
- 不要在 GUI 重构名义下偷偷改变计算语义
- 不要声称当前阶段已经提升了电磁精度
